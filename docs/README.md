# Loom 文档体系

脚手架内置的分层文档体系。每份文档只回答一个问题，按需进入对应层；本体系随脚手架交付，派生项目沿用同一结构（见[新项目接手指南](#新项目接手指南)）。

## 体系图

```
product/vision      方向与红线 —— 只被引用，不引用下层
    ↓ 约束
product/prd         功能规格 + 决策记录（技术架构决策在 adr/）
    ↓ 具体化
product/mvp         落地剧本        dev/ ops/   实现规范与操作参考
    ↓ 排期                                    （引用上层，不定义方向）
product/backlog     epic 任务池 ──→ task/active   执行级任务文档
    ↓ 完成回流
ROADMAP             阶段状态台账（唯一允许「指向上层 + 记状态」的枢纽）

adr/                架构决策记录     archive/    过期存档（文首标注取代关系）
```

## 各层职责

| 文档                                     | 回答的问题               | 写什么                                  | 不写什么                  | 变更频率 |
| ---------------------------------------- | ------------------------ | --------------------------------------- | ------------------------- | -------- |
| [product/vision.md](product/vision.md)   | 我们要去哪？什么不能做？ | 终态、红线、核心概念、非目标            | 实现细节、当前进度        | 低       |
| [product/prd.md](product/prd.md)         | 内置能力做到什么程度？   | 范围、F 编号规格 + 验收、决策记录、指标 | 愿景终态、任务排期        | 中       |
| [product/mvp.md](product/mvp.md)         | 第一个版本怎么跑通？     | 端到端步骤、上线检查清单、验证指标      | 功能规格（引用 PRD 编号） | 中       |
| [product/backlog.md](product/backlog.md) | 确认要做但还没做的？     | epic：做什么/为什么/来源                | 规格、排期承诺            | 中       |
| [ROADMAP.md](ROADMAP.md)                 | 各阶段现在到哪了？       | 阶段状态、关键产物、日期                | 任务明细（引用 backlog）  | 高       |
| [dev/](dev/)                             | 系统怎么实现/怎么开发？  | 健康检查清单、错误处理、上传、参考模块  | 方向性决策                | 中       |
| [ops/](ops/)                             | 怎么部署/配置/运维？     | 部署指南、环境变量参考                  | 产品逻辑                  | 低       |
| [adr/](adr/README.md)                    | 关键架构为什么这么定？   | 背景/选项/决策/权衡                     | 产品功能决策（归 prd.md） | 低       |
| [task/](task/README.md)                  | 当前任务做到哪一步了？   | 执行级任务文档（active/completed）      | epic 级规划（归 backlog） | 高       |
| [archive/](archive/)                     | 历史决策依据是什么？     | 原样保存 + 取代关系标注                 | ——                        | 冻结     |

**粒度检验法**：读完该层文档能否不读下一层就行动？vision 让维护者拍方向，PRD 让开发者写验收用例，剧本让实施者跑通现场，各层自洽。

## 配合规则

### 引用只向下

上层（vision/prd）永不引用下层细节；下层引用上层用锚点或编号（如「vision R3」「PRD F7」「ADR-004」）。唯一例外是 ROADMAP：它向上指、向下引流，但只记录状态。

### 一处一定义

每个事实只在一处定义：红线 → vision；功能规格 → PRD（F 编号）；技术决策 → adr/（引用编号，不转述）；任务明细 → backlog 或 task/；阶段状态 → ROADMAP。发现同一事实多处定义，收敛为「一处定义 + 他处引用」。

### 变更触发矩阵

| 事件             | 动作                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------- |
| 新想法/新需求    | 过 [vision](product/vision.md) 红线检查 → 进 backlog → 排期上 ROADMAP                     |
| 功能完成         | 回写 ROADMAP（产物 + 日期）+ PRD 事实有变则同步 + 从 backlog 移除 + task 文档归 completed |
| 决策拍板         | 产品/工程决策入 prd.md 决策表；架构决策新开 ADR；改主意新增条目，不改历史                 |
| 实现与规划有出入 | 以实现为准刷新 PRD/ROADMAP 事实，并检查是否需修订规划                                     |
| 文档被取代       | 移入 archive/ + 文首标注取代关系 + 全仓更新引用                                           |

### 开发工作流（每次任务）

- **开工前**：读 [ROADMAP](ROADMAP.md) 当前阶段 + PRD 对应功能定义，确认任务归属；新需求先过红线检查
- **执行中**：按 `/task` 技能在 `task/active/` 维护执行文档
- **完成后**：立即回写 ROADMAP；PRD 事实有变则同步

## 新项目接手指南

本体系随脚手架交付。运行 `/init-project` 后按此重置：

| 层                           | 动作                                                                 |
| ---------------------------- | -------------------------------------------------------------------- |
| `product/vision.md`          | **重写**为新项目愿景（一句话定位、红线、术语表），保留章节骨架       |
| `product/prd.md`             | **重写**为新项目 PRD（范围、F 编号规格、决策表），保留结构与验收写法 |
| `product/mvp.md`             | 基本沿用，仅替换项目特定内容（品牌、账号、部署目标）                 |
| `product/backlog.md`         | **清空重建**为新项目任务池                                           |
| `ROADMAP.md`                 | **清空重建**，从「M1 项目搭建」起步                                  |
| `dev/` `ops/` `adr/` `task/` | 原样保留（脚手架技术参考与机制继续有效；ADR 从 ADR-005 续编）        |
| `archive/`                   | 连同脚手架历史一起删除，或保留作溯源                                 |

`/scaffold-clean` 移除 Todo 模块后，同步删除 [dev/todo-reference.md](dev/todo-reference.md)（幽灵引用检查见下）。

**健康检查**（每迭代跑一次）：

- [ ] ROADMAP 与实际进度一致（抽查 2-3 个「已完成」）
- [ ] 无同一事实多处定义
- [ ] 无幽灵引用：`grep -rn "docs/" --include="*.md" .` 列出的每个路径都存在
- [ ] vision 未被实现细节污染（是 → 拆到 dev/）
- [ ] backlog 无已完成项；ROADMAP 未长出规格内容
- [ ] archive/ 文档均有取代关系标注
